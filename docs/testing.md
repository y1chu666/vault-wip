# 测试说明

## 原则

- 测试固定行为，不固定实现。只改实现而不改行为时，测试不应失败。
- 安全相关的行为必须有反向测试：该拒绝的请求确实被拒绝。
- 测试用密钥在运行时生成，不写入仓库。
- 测试中出现的主机名、端口、设备名一律使用保留域名与示例值。

## 分层

1. **插件单元测试**：采集输出的解析、路径归一、上报节奏与防抖、提醒判定、配置读写、签名与加密。
2. **端到端测试**：两台模拟设备经真实中继交换记录，验证注册、频道标识、跨语言签名与加密载荷是否对得上，以及冲突判定是否按预期发生。用例会现场编译并启动中继，因此需要本机有 Go 与 WIP Relay 的源码；缺任一项时整组跳过，不影响日常测试。
3. **渗透测试**：面向中继接口与插件产物，由独立于实现过程的第三方执行；只记录结论，不保留产物。

## 测试数据

- 主机名使用 `relay.example.com`、`relay.invalid` 一类保留域名。
- 设备名使用 `device-a`、`device-b`。
- 频道名使用 `vault-example`。
- 一切密钥、凭证与令牌均在测试运行时生成。

## 持续集成

- 每次提交与合并请求运行类型检查、代码检查、全部测试与构建。
- 覆盖率门禁为百分之九十，低于门禁即判失败。
- 覆盖率只统计 `src/core/` 下的核心逻辑：Obsidian 胶水层不写单元测试，它足够薄，且行为由人工在真实仓库中核对。
- 端到端测试在持续集成中跳过：中继源码位于另一个仓库，构建环境不包含它。
- 发布产物在流水线中构建，产物不进入版本库。

## 不进入持续集成

- 端到端测试，除非在本机同时准备了两个仓库的源码。
- 渗透测试。
- 需要外网、真实主机或真实证书的用例。
- 性能与压力测试，按需手工执行。
