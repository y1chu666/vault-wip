# 设计说明

本文说明 Vault WIP 要解决的问题、核心判断与各项取舍。通信细节见[协议](https://github.com/y1chu666/wip-relay/blob/main/docs/protocol.md)，插件行为见[插件说明](client.md)，服务端行为见[服务端说明](https://github.com/y1chu666/wip-relay/blob/main/docs/server.md)。

其中的插件是 Obsidian 桌面版插件：界面、设置与状态栏都借助 Obsidian 提供的能力。中继服务端独立运行，不依赖 Obsidian，也可以只当作一个通用的状态转达服务使用。

## 目标与场景

同一个笔记仓库往往在多台机器上使用。若机器同时开机，冲突可以当场发现；真正的麻烦发生在机器交替使用、彼此不同时在线的时候：

1. 机器甲上留有未提交的改动，使用者关机离开。
2. 机器乙继续撰写，提交并推送。
3. 使用者回到机器甲，执行拉取，冲突就此出现。

到这一步，损失已经发生。版本控制只在此刻提示冲突，而这一提示本可以更早给出。Vault WIP 的目标是把提示提前到动笔之前：在打开文件、保存、切换窗口时告知使用者，对端仓库里是否仍有未提交的改动。

由此确定本项目采集的信号：

**对端设备上，属于同一仓库的未提交改动。**

不是提交记录，不是最后一次同步时间，也不是在线状态。提交记录由版本控制自身可见，无需重复；真正缺失的信息，是「对端还有没写进提交里的东西」。

## 适用与不适用

适用：多台桌面设备交替使用同一仓库，且都安装了本插件并配置了可达的中继。

不适用：需要真正同步内容的场合。本工具只提示状态，不搬运文件。

## 系统组成

- **插件**：运行于 Obsidian 内，采集本地仓库状态，与其他设备交换记录，在需要时提醒使用者。
- **中继服务端**：接收并保存各设备的状态记录，供其他设备读取。它不参与内容，也不掌握密钥。

一台设备可以只连一个中继，也可以连多个。多个中继之间不互联，差异由客户端在可达的中继之间补齐。

## 身份与信任

每台设备首次运行时在本机生成一对非对称密钥，设备身份即其公钥的指纹。服务端不分配标识，只认指纹。

设备发出的请求都带签名；服务端对响应也签名；客户端在首次配对时钉住服务端公钥，此后只接受由该公钥签名的响应。

信任是平级的：既无管理员，也没有哪台设备高于其他设备。

## 记录与一致性

交换的记录分两类：

- **状态记录**：某台设备在某个仓库上的未提交状态概览，含改动文件数与文件名列表摘要。
- **吊销记录**：某台设备被判定不再可信。

状态记录由设备本人签名并携带单调递增的序号。序号由设备自行推进，服务端只负责保存与转达，不得代替设备推进。如此即便中继被替换或回滚，客户端也能凭序号判断新旧。

吊销的作用范围限定在同一个仓库对应的频道之内：频道内任一设备都可以吊销任一设备，但有一条防自锁规则——不允许吊销频道内最后一台可用设备。吊销只是记入名单，设备仍留在列表里，因此「可用」要按未被吊销的设备数来数，判断与写入也要在同一临界区里完成。

退役不等同于清理状态。退役会删除该设备的数据、将其移出设备列表，并记入吊销名单，且不可逆；要恢复只能重新注册。

## 保密

设备之间交换的记录用对称加密保护，密钥按仓库划分，密文带密钥标识。密钥分发有三种并存方式：口令派生（强度较弱，须明确标注）、随机密钥串（默认推荐）、导出与导入文件。

设备私钥永不导出、永不导入，也不离开生成它的机器。内容密钥可以导出与导入，但导出前必须提示；默认导出内容不含密钥。

界面也是一条泄露途径：截图与旁人视线不需要任何权限。因此视图把频道标识与各类指纹默认遮去中段、只留首尾各四位，中继地址保留协议与顶级域、按主机类型遮住其余部分，需要核对时点眼睛展开；中继名称与仓库别名保持明文，它们本就为辨认而设，遮住反而失去用途。地址的遮罩刻意留出辨认所需的字符：整段遮死就分不清是哪台服务器，遮蔽的价值要落在「旁人读不全」，而不是「自己也认不得」。

## 传输

连接分四级，安全强度依次降低：

1. 公网证书的 HTTPS。
2. 钉住自签证书的 HTTPS。
3. 忽略证书错误的 HTTPS。
4. 明文 HTTP。

默认只允许前两级。后两级必须显式开启，且一经开启不得自动回退到更低级别；处于降级状态时禁止执行破坏性操作。注册默认要求 HTTPS。

第三级只是不校验证书链，证书本身仍要读得出来：读不出来的连接照旧失败。忽略证书错误不等于放行一个不表明身份的对端。

## 提醒

提醒遵循「宁可少弹，不可乱弹」：

- 对端改动与本地改动落在同一文件时，视为真冲突，立即通知。
- 每次启动后，若任一已配对设备存在未提交改动，通知一次。
- 持续故障按可配置间隔重提醒，默认十分钟，可以关闭。
- 只在窗口获得焦点时弹出。
- 故障恢复时通知一次。

常驻状态由状态栏承载，不靠弹窗反复提示。

## 配置

配置以文件为唯一事实来源，界面只是编辑器。插件与服务端使用同构的配置格式，便于手工修改与导入。格式为带版本号的 TOML；配置与运行状态分开存放；服务端提供重载配置的子命令，不依赖信号。

## 明确不做

- 不做移动端。
- 不上传笔记内容。
- 不执行任何 git 写操作。
- 不设管理员角色。
- 不提供独立命名的恢复命令行工具，恢复由服务端子命令承担。
- 不试图替代 Obsidian Git。

## 关键决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 项目命名 | 插件展示名 Vault WIP，仓库 `vault-wip`；服务端仓库 `wip-relay` | 插件面向 Obsidian 用户，服务端面向任何 Git 仓库，两者各自独立、说明互链 |
| 服务端语言 | Go | 单一二进制，跨平台部署简单 |
| 身份 | 设备本地生成密钥对，身份为公钥指纹 | 无需中心分配，服务端不持有身份来源 |
| 序号推进 | 由设备本人签名推进 | 服务端不得代劳，避免中继伪造状态 |
| 吊销 | 限同一频道，禁止吊销最后一台可用设备 | 平级信任下最简可行，且不会自锁 |
| 退役 | 取代「仅清状态」，不可逆 | 单向单调，无需比较新旧 |
| 多中继 | 互不互联，由客户端搬运 | 省去中继间鉴权与复制协议 |
| 加密 | 每个仓库一把内容密钥，AES-256-GCM | 服务端只搬运密文 |
| 传输 | 分四级，禁止自动降级 | 防止中间人诱导降级 |
| 节奏 | 定时十五秒，关键事件立即上报 | 兼顾及时与开销 |
| 提醒 | 真冲突立即，其余克制 | 避免提示疲劳 |

## 实施中已定的细节

以下原本待定，实现时按此收口：

- 服务端默认监听 `127.0.0.1:8787`，主机不得省略，避免误绑全部网卡。
- 每台设备在中继上保留的记录条数与单条记录的字节上限都由服务端配置给出，超出即拒收并报明原因。
- 状态记录里的文件名列表上限一千条，超出即截断并标注 `truncated`，使记录大小可控。
- 上报回送有确定的字节上界，取在客户端自身的响应上限之下：记录与吊销名单合起来不超过它，吊销名单另有一份更小的份额，超出即截断并标注。被拒时回送的既有记录优先于其余记录，它是本设备继续上报的唯一线索。
- 频道的吊销名单有配置上限，默认一千零二十四条，保存与回送两侧都受约束，达到上限后不再接受新的吊销与退役：这份名单只增不减，而每次上报都要整份回送。
- 设备名称允许重名：身份始终按指纹区分，名称只用于显示，不予校验。
- 界面上的中继列表与密钥分发集中在设置页与状态视图的「安全」一栏；配置的编辑集中在设置页，视图只显示状态与触发动作。
- 冲突残留文件的识别做成配置开关，默认开启；识别结果只影响措辞，不影响是否算冲突。
- 诊断信息只包含本机采集耗时、事件、被舍弃的对端记录与序号异常，各保留最近五十条；不含文件内容，也不含任何密钥。
- 配置版本不符时报错并要求人工处理，不做自动迁移：迁移写错比报错更难发现。
- 界面文案以中文为准并另备英文译文：中文原句兼作文案键，译文表由类型检查约束，漏译即编译不过；语言默认跟随 Obsidian 的界面语言，也可以在设置页固定成中文或英文。
- 允许插件主动查询远端：只查一个远端（设置页指定，留空用当前分支的上游），只用 `ls-remote` 一类的查询子命令，不拉取、不改本机引用；结果只在本机界面上显示，不进记录、不上报，因此不改协议。查询按远端地址在仓库之外发起：远端地址先读出来，仓库自己的 git 配置（取回程序、地址改写、凭证助手）就不再参与这一步。自动查询的最短间隔可在设置页调整，默认十分钟，设为 0 表示不自动查询。
- 许可协议取 Apache-2.0：允许商用与再分发，改动过的文件须注明改动，附带专利授权与责任免除；版权行写在许可证正文末尾，署名保持中性。
