# 插件说明

本文说明 Obsidian 插件的行为：如何采集、何时上报、何时提醒、界面如何组织。通信细节见[协议](https://github.com/y1chu666/wip-relay/blob/main/docs/protocol.md)。

## 采集

采集只读取，绝不写入。使用 `git status --porcelain=v2 -z`，并以分支信息补充，结果包含未跟踪文件。

- 固定环境变量 `LC_ALL=C` 并关闭可选锁，避免输出受语言环境与并发影响。
- 不主动拉取远端，采集结果只反映本机工作区。
- 路径统一做小写归一与 Unicode 归一，且以仓库根为基准，避免同一文件在不同平台上被判为不同。
- git 可执行文件路径允许自定义，启动时以 `git --version` 校验。
- 每条命令都带上取值压过仓库自身配置：关掉 `core.fsmonitor`、清空 `diff.external`，差异命令另行关掉外部差异程序；每次采集之前还会取出仓库本地配置里定义过的过滤器驱动（含 include 引来的文件与工作区配置两处），逐个清空其 clean、process 与 smudge 并标为非必需；这组取值通过环境变量随命令带过去，因为驱动名本身可以含等号，走 `-c` 会被拆错键。仓库的 `.git/config` 与属性文件都随仓库一起被克隆或同步，属于别人可以影响到的内容；采集只是只读查询，不该因为跑一次 `git status` 就以本进程的权限执行仓库指定的程序。全局配置里的过滤器不动：那是本机自己的内容。
- 由此带来的取舍：仓库若靠本地配置的过滤器改变工作区内容的表示，那些文件在采集结果里会被判为有改动。宁可按「有改动」提示，也不执行仓库指定的程序。

采集结果包含改动文件数与文件名列表摘要，不含文件内容。

## 上报节奏

- 定时上报，间隔十五秒。
- 启动完成、切换文件、保存、窗口获得焦点时立即上报；同一秒内的多次触发按两秒防抖合并。
- 窗口失去焦点超过五分钟后，间隔降为六十秒。
- 心跳与拉取合并为同一个请求，避免请求数翻倍。
- 每一轮结束之后按当前节奏重排下一次定时，因此改动配置或窗口焦点变化都能即时生效。

状态没有有效期，长期保留；在线与否按最近一次成功通信的相对时长计算。

## 提醒规则

- 对端改动与本地改动落在同一文件时，视为真冲突，立即通知。
- 每次启动后，若任一已配对设备存在未提交改动，通知一次。
- 持续故障按可配置间隔重提醒，默认十分钟，可设为五分钟、十分钟、三十分钟、六十分钟或关闭。
- 只在窗口获得焦点时弹出。
- 故障恢复时通知一次。
- 常驻状态由状态栏承载。

## 界面

插件提供独立视图，分五栏：

1. **概览**：本设备身份、本机改动、与对端重叠的文件，以及远端查询的结果。
2. **各端状态**：逐台设备列出未提交改动与文件清单，可就地吊销。
3. **中继**：各中继的连接状态、频道标识、最近一次成功与最近一次失败。
4. **安全**：加密状态、密钥分发、中继身份指纹与退役；处于降级状态时显著标注。
5. **诊断**：采集耗时、本机计数、事件、被舍弃的记录与序号异常，供排查使用。序号由本设备自己推进，平时无需过问；只有它到了无法继续推进的地步，才在这里核对状态并重置本机计数。

配置项的编辑集中在设置页：本设备名称、仓库别名、界面语言、采集节奏、远端查询、提醒间隔、中继列表与注册。视图只显示状态并触发动作，不在视图里改配置；两处读写的都是同一份配置文件。

设置页每次改动都会把整份配置重新序列化写回文件，再重新解析一遍交给内核，因此校验规则只有一处，界面不另设一套。

## 配置与本地数据

配置以 TOML 文件为唯一事实来源。本设备名称写在配置里（`[device] name`），随加密的记录内容一起传给同仓库的其他设备；中继看不到它。同名设备可以并存，身份始终按指纹区分，名称只用于显示；留空时对端只按指纹的前八位称呼本设备。

配置、设备私钥、内容密钥、钉住的中继公钥与状态缓存都放在插件目录下（`.obsidian/plugins/vault-wip/`），依次为 `config.toml`、`device.key`、`content.key`、`pins.json` 与 `state.json`；导出密钥时另会写出 `content-key.export` 或 `content-key.protected`。密钥文件旁会写一个 `.gitignore`，只列出这些密钥文件名，使这个目录被版本控制时不会把它们一并提交；设置页与文档也都提示不要纳入版本控制。若使用者把整个 `.obsidian` 目录提交或随仓库同步，密钥就会随之外流，这一点无法由插件代为保证。

首次运行时写下的配置样例，以及密钥目录的忽略清单，都带说明注释；注释按写下当时的界面语言写出。此后由设置页改写配置时不再保留注释，需要长期留着注释的使用者应当直接编辑文件。

频道标识由各中继分别生成，因此状态缓存按中继名分别记录频道标识与别名：同一仓库在两台中继上是两个不同的频道标识，记录签名也按中继分别做。

密钥分发有三种方式，配置与文档一律推荐随机密钥串：

- **密钥串**：直接抄写或就近传递，强度最高，更依赖双方保管得当。
- **口令封装**：文本仍需口令才能解开，可以走不那么可信的渠道。派生使用运行时自带的 scrypt，代价参数随文本自带，将来调高参数不会让旧文本失效；口令分发本来就是三种里较弱的一种，界面与文档都照此标注。
- **导出与导入文件**：把上面的文本写成文件，或把拿到的文本粘贴回来。设备私钥永不导出。

界面文案以简体中文为准，另备英文译文。设置页的「界面语言」可以固定用中文或英文，默认跟随
Obsidian 的界面语言：语言代码以 `zh` 开头就用中文，其余用英文。译文以中文原句为键，漏译一条
就通不过类型检查，因此英文界面里不会夹着中文句子。读界面语言用的是 Obsidian 自 1.8.7 起提供
的公开接口，清单里的最低版本随之提到 1.8.7。

一句话在拼接时就已定下语言，因此切换语言只影响此后新产生的文字；诊断与事件里先前的条目保留
写入时的语言。命令名在插件加载时注册，改了语言之后要重新加载插件才会跟着变。设计文档、代码
注释与提交信息仍为中文，README 另有英文版。

## 远端查询

设置页可以指定一个远端（例如 `origin`），留空则用当前分支的上游。插件会向它问一次各分支指向哪笔提交，并与本机比较，分出四种情形：两边一致、本机有提交尚未推上去、远端有提交本机还没有（那笔提交本机还不认识时会单独说明）、以及两边已经分开。结果只显示在状态视图的「概览」一栏，附带查询时刻，并可以随时按「查询远端」再查一次；启动后会自动查一次，此后最多每十分钟自动查一次。

查询是只读的：`ls-remote` 只问一句远端有哪些引用，不把远端的东西取回本地，也不写任何引用，更不会替你拉取。查询这一步也不在仓库目录里发起，而是先把远端地址读出来，再拿着地址去问（地址以短横线起头时直接跳过：那种写法会被 git 当成选项，例如 `--upload-pack=…`）；仓库自己的 git 配置（为该远端指定的取回程序、地址改写、凭证助手之类）都能写成一条命令，留在仓库里查询就会被它们牵动，因此这一步挪出仓库。结果只留在本机，不进记录、不上报，中继与对端都不知道你查过谁、查出了什么。中继联系不上与远端查不通是两回事：前者影响上报与对端提示，后者只影响这一栏显示的内容。

## 假冲突识别

以下情形会造成「看似有改动，实则无需担心」，需要识别并在展示时标注：

- 行尾转换设置（`core.autocrlf`）导致的整文件差异。
- 文件权限位变化（`core.fileMode`）导致的模式差异。

识别结果只影响提示措辞，不修改仓库设置。

## 边界情形

- 仓库不存在或 git 不可用：不上报，由状态栏提示，不重复弹窗。
- 仓库尚未加入任何频道：提示尚未注册，不静默失败。
- 中继全部不可达：本地状态照常采集，待恢复后一并上报。
- 时钟偏差过大：提示校正时间，暂停签名通信。
- 设备被吊销：立即停止上报，清理本地缓存，提示需重新注册。
- 上报被拒（序号不大于中继已有记录）：采用回送中的既有记录，把序号推进后重报一次；重报仍被拒时如实说明。这通常意味着本地状态被回退，或同一身份被复制到了两台机器上，诊断栏要留痕。中继给出的既有序号若已到可表示上界，则不予采信：采信它会让本机计数停在无法再加一的位置，此后一次也报不上去，连重置都会被立刻顶回来。采信之前还要核对该条记录确实由本机签名：中继只负责搬运，核不过签名、或那条记录根本不属于本机的，都不影响本机计数。
- 序号越过 2^53-1：不再上报，说明原因并指向诊断栏的重置入口。单独的某一条越界或不成形的记录、吊销纪录只被舍弃，不影响同一次回送里的其余条目。
- 中继回送的记录或吊销名单被截断：如实写入诊断，本次视图不完整，其余条目等下一轮再取。
- 多台中继并存时，某一台上的记录落后于另一台属于常态，因此只有「同一序号给出两份内容」才算异常并留痕，序号回退不重复提示。
- 中继公钥随每次响应以响应头给出：首次配对时先收下并记下指纹，此后每次核对，换了钥匙即停止通信。
- 对端公钥不需要单独钉住：指纹本身就是公钥的摘要，校验「指纹与公钥相符」即可。恶意中继只能伪造全新身份，不能冒充既有对端。
- 对端公钥与钉住值不符：不再采用该设备的记录，提示重新核对，不自动改写钉住的公钥。
